# NEAT Assistant Retrieval Development

The assistant knowledge base is evaluated before it is connected to a language model. This separates retrieval failures from answer-generation failures.

## Approved knowledge files

The explicit loader accepts only:

- `faq.md`, `troubleshooting.md` and `parameter_reference.md`;
- the user-facing software/UI guide and menu reference;
- the curated preprocessing, fitting, mapping and post-processing technical
  guides; and
- `known_limitations.md`.

It does not ingest the complete `docs/technical` tree. New technical material
must be reviewed, rewritten for users, explicitly added to the loader and
covered by evaluation questions.

`software_ui_guide.md` explains the visible workspaces, interface management,
ROI interactions, remembered settings and Clear commands.
`menu_reference.md` explains every current top-level menu action and keyboard
shortcut. `fitting_ui_reference.md` covers the fitting controls and their
dialogs in detail. Keep their labels synchronized with the application UI.

## Install the optional semantic retrieval tools

From the repository root:

```powershell
python -m pip install -e ".[assistant]"
```

These dependencies are optional and are not installed with the normal NEAT application.

## Run the dependency-free BM25 baseline

```powershell
python -m tools.evaluate_assistant_retrieval --top-k 3 --show-misses
```

## Compare BM25 with local semantic retrieval

```powershell
python -m tools.compare_assistant_retrieval --top-k 3 --show-misses
```

The semantic benchmark uses LangChain's Chroma integration and Chroma's local ONNX `all-MiniLM-L6-v2` embedding model. The model is downloaded automatically on first use. Generated vector indexes are stored under `.assistant_cache/` and are excluded from Git.

## Evaluate question routing and safety escalation

```powershell
python -m tools.evaluate_assistant_router --show-errors
```

Inspect the complete route-aware semantic pipeline for one question:

```powershell
python -m tools.query_assistant "Why is my Bragg-edge fit unstable?"
```

The router selects a response policy before retrieval. Requests for guaranteed scientific correctness are routed to mandatory escalation and the approved escalation guidance is pinned as the first source.

## Preview grounded answer generation

Run the complete route, retrieval, prompt, answer and citation flow without an API key:

```powershell
python -m tools.preview_assistant_answer "What does eta represent?"
```

This command uses an extractive offline preview model. It verifies the wiring but is not the production conversational model. The production layer accepts any LangChain-compatible chat model through its standard `invoke(messages)` interface.

The language model receives strict instructions and approved NEAT source text. Route, human-review status and citations are controlled by the application. Citations are built from retrieved metadata and cannot be replaced by source identifiers generated by the model.

## Connect OpenAI

The API key is read from the environment and must never be committed to the repository.

For future PowerShell windows:

```powershell
setx OPENAI_API_KEY "your_api_key_here"
```

Open a new PowerShell window after using `setx`. For the current window only:

```powershell
$env:OPENAI_API_KEY = "your_api_key_here"
```

Then run a grounded live question:

```powershell
python -m tools.ask_neat_openai "What does eta represent?"
```

The default model is `gpt-5.6-luna`. Override it without changing source code:

```powershell
$env:NEAT_ASSISTANT_MODEL = "another-model-id"
```

Only the question, selected safe application context, recent chat turns and retrieved documentation passages are sent to OpenAI. Raw experimental images and files are not included by this command.

## Use the assistant inside NEAT

Start NEAT normally:

```powershell
python -m NEAT.app
```

The **NEAT AI Assistant** opens as a dockable panel on the right. It can also be
shown or hidden using **AI Assistant > AI Assistant** or `Ctrl+Shift+A`. Open
**AI Assistant > AI Assistant Settings...** to select access and model
settings. Enter a question and choose **Ask**, or press `Ctrl+Enter`.

Choose **Explain current screen** to ask for an overview of the active workflow,
its main controls, prerequisites and cautions. The action uses the same
allow-listed screen context and preserves text already drafted in the question
box.

The panel displays the generated answer and a separate list of verified NEAT sources. Its recent conversation is kept in memory only and is cleared when NEAT closes. Selected fitting-page settings may be supplied as context, but file paths and raw images are excluded.

After an answer, the user can choose **Helpful** or **Not helpful**. Feedback is
stored locally at:

```text
%LOCALAPPDATA%\NEAT\assistant_feedback.jsonl
```

Each line contains the rating, typed question, verified source identifiers,
route, review flag, NEAT version and timestamp. It does not contain the
generated answer, selected application context or raw images. NEAT does not add
application file paths, and Windows-style paths typed directly in a question
are replaced with `[local path removed]` before logging. Submitting feedback is
optional, and one rating is accepted for each answer.

## Run a real-use pilot

Use the conversational checklist in
[`pilot_questions.md`](pilot_questions.md) to collect at least 20 ratings across
preprocessing, fitting, post-processing and scientific-boundary questions.
These prompts are deliberately different from the controlled evaluation set.

After adding or substantially changing curated technical knowledge, use
[`technical_pilot_questions.md`](technical_pilot_questions.md). It contains
four short sessions covering preprocessing rules, wavelength/fitting details,
mapping outputs and post-processing boundaries.

After collecting feedback, create a local Markdown summary:

```powershell
python -m tools.summarize_assistant_feedback
```

The report shows both the complete rating history and the latest rating for
each distinct question, plus route coverage, commonly cited sources and
currently unresolved Not-helpful questions. Retesting a corrected question as
Helpful therefore resolves it without deleting the original audit record. The
tool reads only the local feedback log and does not call OpenAI. Use `--input`
and `--output` to select alternative paths when required.

### OpenAI 429 errors

If the command reports `insufficient_quota`, the API key was accepted but its API project has no available billing quota. Add API credit or increase the project budget in the OpenAI Platform billing settings. A ChatGPT subscription and OpenAI API billing are separate.

If it reports `rate_limit_exceeded`, wait briefly and retry. Persistent request or token limits can be reviewed in the OpenAI Platform project limits settings.

## Evaluate live answer quality

First inspect the planned number of questions without making API requests:

```powershell
python -m tools.evaluate_assistant_answers --limit 3
```

Run a small billable pilot after confirming the API key and credit are configured:

```powershell
python -m tools.evaluate_assistant_answers --limit 3 --confirm-live
```

Run all curated questions:

```powershell
python -m tools.evaluate_assistant_answers --confirm-live
```

Reports are written under `.assistant_cache/evaluations/` as JSON plus a Markdown human-review form. Progress is saved after every question. To resume an interrupted named report:

```powershell
python -m tools.evaluate_assistant_answers `
  --output .assistant_cache/evaluations/my_report.json `
  --resume --confirm-live
```

The automatic checks verify expected source citations and mandatory escalation behaviour. Key-point coverage is deliberately labelled as a lexical heuristic. Correctness, groundedness, clarity and scientific scope must be scored by a human reviewer from 0 to 2.

Use `--rebuild` after changing embedding behaviour. Changes to the approved knowledge files automatically produce a new fingerprinted Chroma collection.

## Metrics

- **Hit@1:** expected source is the first result.
- **Hit@3:** expected source is present in the first three results.
- **MRR:** mean reciprocal rank; higher values indicate that expected sources appear earlier.

The evaluation set is `evaluation_questions.json`. Each question declares one or more acceptable source sections and the key points that a later answer-generation stage should contain.
